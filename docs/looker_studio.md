# Looker Studio 展示層建置規格

讀取 BigQuery `housing_gold` 的 4 張分析表，做成 5 頁報表，用一個連結分享。照本文件由上而下操作即可，預估 2–3 小時。各表的口徑與限制見 [marts.md](marts.md)。

> Looker Studio 介面會改版，按鈕名稱以實際畫面為準；本文件寫的是要達成的設定，不是逐一點擊的位置。

## 1. 建立資料來源（4 個）

在 [Looker Studio](https://lookerstudio.google.com) 建立空白報表 → 新增資料 → **BigQuery** → 我的專案 → `taiwan-household` → `housing_gold`，依序加入：

| 資料來源名稱（建議） | 資料表 | 用在 |
| --- | --- | --- |
| 全市月市場 | `agg_city_month_market` | 第 1 頁 |
| 各區季趨勢 | `agg_district_quarter_price` | 第 2 頁 |
| 型態屋齡差異 | `agg_district_segment_price` | 第 3 頁 |
| 預算能買到什麼 | `agg_district_budget` | 第 4 頁 |

每個資料來源都要做兩項設定：

- **資料憑證設為「擁有者的憑證」**。這樣看報表的人不需要 BigQuery 權限，查詢用你的帳號執行。資料量很小（每張表不到 150 列），不會產生費用。
- **資料更新頻率**：預設 12 小時即可，資料一季才更新一次。

## 2. 欄位設定與計算欄位

**通用規則**（4 個資料來源都適用）：

| 欄位 | 設定 |
| --- | --- |
| 名稱含 `ratio` 或 `share` 的欄位 | 類型改為「百分比」。資料是小數（0.05 = 5%），Looker 會自動顯示成 5% |
| `transaction_quarter` | 類型改為「年份季度」 |
| `transaction_month` | 類型改為「年份月份」 |
| `deal_count` 等計數欄位 | 彙總方式設為「總和」 |
| 中位數、分位數、比率欄位 | **彙總方式設為「無」或「平均值」，不可用「總和」**。表中每列已經是算好的結果，加總會產生錯誤數字 |

**計算欄位**：在資料來源編輯畫面中新增，公式直接貼上。

單價改為萬元（全市月市場、各區季趨勢、型態屋齡差異、預算能買到什麼都要加）：

```
中位單價（萬／坪） = median_price_per_ping / 10000
```

全市月市場另加：

```
滾動 3 月中位單價（萬／坪） = rolling_3m_median_price_per_ping / 10000
```

各區季趨勢、型態屋齡差異另加：

```
P25（萬／坪） = p25_price_per_ping / 10000
P75（萬／坪） = p75_price_per_ping / 10000
```

型態屋齡差異：建物型態中文標籤

```
建物型態 =
CASE
  WHEN building_type_group = "tower" THEN "住宅大樓"
  WHEN building_type_group = "mansion" THEN "華廈"
  WHEN building_type_group = "apartment" THEN "公寓"
  WHEN building_type_group = "townhouse" THEN "透天厝"
  ELSE "其他"
END
```

預算能買到什麼：排序用欄位。文字排序會把 `<1000` 排到最後，用這個欄位排序：

```
預算帶排序 =
CASE
  WHEN budget_band = "<1000" THEN 1
  WHEN budget_band = "1000-1500" THEN 2
  WHEN budget_band = "1500-2000" THEN 3
  WHEN budget_band = "2000-3000" THEN 4
  WHEN budget_band = "3000-5000" THEN 5
  ELSE 6
END
```

屋齡帶 `0-10`、`10-30`、`30+`、`unknown` 照文字排序剛好正確，不需要額外處理。

## 3. 頁面規格

報表主題建議選淺色，頁面尺寸 1200 × 900。每頁右上角放一個文字框寫「資料：內政部實價登錄，台北市住宅買賣，2023-10 ~ 2026-03」。

### 第 1 頁：市場總覽（資料來源：全市月市場）

回答「市場現在冷還是熱」。

| 元件 | 設定 |
| --- | --- |
| 計分卡 ×3 | 最新月（2026-03）的 `deal_count`、滾動 3 月中位單價（萬／坪）、`deal_count_yoy_ratio`。用「日期範圍」或篩選器固定在最新月 |
| 組合圖（主圖） | 維度 `transaction_month`；長條 = `deal_count`（左軸）；折線 = 滾動 3 月中位單價（萬／坪）（右軸）。篩選器：`is_rolling_window_complete` = true（排除最前面 2 個月不完整窗口） |
| 文字框 | 「2024-10 起月成交量由約 1,000–1,300 筆降到 500–750 筆，年減 30–48%，與 2024 年 9 月信用管制時間點吻合；本資料無法證明因果。」 |

### 第 2 頁：哪一區在漲（資料來源：各區季趨勢）

| 元件 | 設定 |
| --- | --- |
| 下拉式清單控制項 | 維度 `district`，允許多選，預設全選 |
| 時間序列圖 | 維度 `transaction_quarter`；細分維度 `district`；指標 中位單價（萬／坪） |
| 長條圖 | 最新一季（篩選 `transaction_quarter` = 2026 Q1）各區中位單價，由高到低排序 |
| 表格 | 維度 `district`、`transaction_quarter`；指標 `deal_count`、P25、中位單價、P75、`median_yoy_ratio`。`median_yoy_ratio` 用條件式格式：> 0 綠色、< 0 紅色 |
| 說明文字 | 「年增率在去年同季無資料或樣本少於 30 筆時留空。中位數受屋齡與型態組成影響，不是房價指數。」 |

### 第 3 頁：新大樓與老公寓差多少（資料來源：型態屋齡差異）

| 元件 | 設定 |
| --- | --- |
| 核取方塊控制項 | 欄位 `is_low_sample`，標籤「隱藏樣本少於 30 筆的格子」。預設勾選 = 只顯示 false |
| 下拉式清單控制項 | 維度 `district` |
| 樞紐分析表（含熱度圖） | 列 = 建物型態；欄 = `age_band`；指標 = 中位單價（萬／坪），聚合方式「平均值」（每格只有一列，平均值等於原值）。選定單一區時才有意義，所以搭配上方的區域控制項 |
| 長條圖 | 維度 `district`；細分 建物型態；指標 中位單價（萬／坪）。篩選 `age_band` = `0-10` 或 `30+` 比較新舊 |
| 說明文字 | 「每格合併 2023-10 ~ 2026-03 全部交易。公寓幾乎都超過 30 年、透天厝很少，所以很多格子樣本不足，這反映台北的實際存量。透天厝單價含土地價值，不與公寓大樓直接比較。」 |

選單一區時，樞紐表的值才是那一區的中位數；選多區時 Looker 會把各區的中位數再平均，這不是正確的全市中位數。全市層級的比較請看 [marts.md](marts.md) 裡從逐筆交易算出的數字。

### 第 4 頁：預算能買到什麼（資料來源：預算能買到什麼）

| 元件 | 設定 |
| --- | --- |
| 下拉式清單控制項 | 維度 `budget_band`，單選，預設 `2000-3000`；排序欄位用「預算帶排序」 |
| 長條圖 | 維度 `district`；指標 `median_housing_area_ping`（中位坪數），由高到低。標題：「這個預算在各區的中位坪數」 |
| 表格 | 維度 `district`；指標 `deal_count`、`share_of_district_deals`、`median_housing_area_ping`、`median_building_age_years`、`median_room_count`、`elevator_share`、`parking_included_share`、中位單價（萬／坪）。`median_building_age_years` 加長條格式 |
| 說明文字 | 「近 12 個月（2025-04 ~ 2026-03）。預算為含車位總價；含車位交易的比例見『車位比例』。房數中位數排除申報為 0 房的交易。」 |

### 第 5 頁：資料與方法

純文字頁，給面試官或讀者看口徑。建議內容：

- 資料來源：內政部地政司實價登錄開放資料，政府資料開放授權條款第 1 版。
- 範圍：台北市住宅買賣（主要用途為住家用），2023-10 ~ 2026-03，共 23,716 筆。
- 排除：非房地交易、特殊關係、預售屋與分件登記、車位無法拆算、重複編號等，規則見 GitHub repo。
- 單價口徑：扣除車位後的價格 ÷ 扣除車位後面積，換算為每坪。
- 中位數、分位數都由逐筆交易計算；樣本少於 30 筆的格子已標記。
- 本報表是描述性統計，不是房價指數，也不代表政府官方統計。
- 資料管線：Python 載入 → BigQuery（bronze／silver／gold）→ dbt 測試 → Airflow，原始碼連結放在這裡。

## 4. 分享

右上角「分享」：

- 一般存取權：「知道連結的任何人」→「檢視者」。
- 確認 4 個資料來源都是「擁有者的憑證」，否則別人打開會看到權限錯誤。用無痕視窗打開連結測試一次。
- 不要給「編輯者」權限，編輯者可以看到並修改資料來源設定。

## 5. 維護：資料表到期

BigQuery sandbox 的資料表在建立後 60 天自動刪除，目前到期日是 **2027-01-16**。到期後報表會出現資料來源錯誤。

- 每次執行 Airflow DAG 或 `dbt build`，表會重建，到期日自動往後推 60 天。到期前跑一次即可。
- Bronze 的季表也會到期，所以要跑完整的 DAG（含下載與載入），不能只跑 dbt。
- 想永久保留，可以為 GCP 專案啟用計費帳戶並移除 dataset 的預設到期時間。以本專案的資料量，費用應接近 0，但仍要設定預算警示。

重建後資料表名稱不變，Looker Studio 不需要重新設定。
